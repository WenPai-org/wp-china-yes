## 任务书模板

完整可复制稿与 DoD 清单见 [`task-book-template.md`](task-book-template.md)。每个任务必须有这些块；缺一块就停，不要猜：

```markdown
# 任务：<短名>

## 目标
一句话。

## 背景与上下文文件
路径列表（仓内 + `.grok-context/`）。不要联网补资料。

## 交付物
路径级。新建 / 只改哪些。

## 行为规格
对照的 spec / ADR / 定稿条目。UI 任务列出规格编号（如 OV-03）与原型路径。

## 禁区
路径、产品决定、文案、git 操作。

## 验收标准
可执行的命令（不只「通过」）。每条都能用一条命令或一张截图证明。

## Definition of Done
见下方固定清单；原文贴进任务书。

## 报告格式
见下节。
```

执行者不是决策者：任务书写死的范围、命名、禁区不得自行更改。任务书矛盾或做不到 → **停下来在最终报告里写明**，不要绕。UI 任务无 [`design-sop.md`](design-sop.md) 认可记录则任务书无效。

### Definition of Done（固定清单）

执行者在报告里逐条打勾并贴证据；缺一条不得报「完成」：

- [ ] 规格条目 ↔ 实现逐条对照表（`| 规格编号 | 实现位置 文件:行 | 状态 |`），规格里有、实现没有的必须列出并写「未做」。
- [ ] 每个状态一张截图（Playwright，命名 `<页面>-<状态>.png`，存 `docs/design/screens/<任务>/`），UI 任务必备；非 UI 任务写「不适用」。
- [ ] 面向用户的字符串：全部中文、在 `admin-ui-spec.md` §4 词表内或已提交词表新增；无英文错误串；无「遥测/隐私/上报」字样。
- [ ] 空状态、错误状态、降级状态有对应实现，不是「空表占位」。
- [ ] 测试：新增/修改行为有测试；`composer check` 与 `npm run build`、`npm run lint:js` 通过；CI run id。
- [ ] `git diff --stat` 在允许路径内；`.grok-context/` 未入库。
- [ ] 报告含「没做 / 做不到 / 有疑问」；**报告写完再退出**（等 CI 时先写「CI run <id> 进行中，本地验收如下」）。

### 任务书写法规则

- **给原文，不给范围**：颜色、尺寸、文案、路径写具体值，不写「大约/范围/类似」。
- **线索标「猜测」**：统筹给的原因分析若未验证，必须写「猜测：」前缀，执行者按证据纠正并在报告写明。
- 任务书里每条验收都要能用一条命令或一张截图证明。

## worktree 与分支

- 每任务一个独立 git worktree，只在该目录改文件
- 分支：`grok/<topic>` 或 `codex/<topic>`，基于任务书给出的 commit
- 可以 `git add` / `git commit`；**禁止** `git push`、切分支、`git reset --hard`、改 `master`/`main`
- 不要把 `.grok-context/` 提交进 git
- 由审批者合并；代理不发版、不打生产 tag（除非任务书写明授权）

## 报告格式

完成后输出中文最终报告，必须含：

1. 改了哪些文件（`git diff --stat` 原样贴出）
2. 每条验收标准的实际执行命令和输出摘要（不要只写「通过」）
3. 任务书里没做、做不到、或有疑问的项，逐条原因
4. 提交哈希（`git log --oneline -5`）

无命令输出支撑的「完成」视为未完成。审批者会先跑验收命令再看 diff。

## 独立核查

另一个代理 **只读** 审查，不接同一份「再改一版让它绿」的指令混进执行会话。审查员不得是写代码的那次运行。分层与视觉表见 [`acceptance-sop.md`](acceptance-sop.md)。代码审查走现有 `review.sh` 流程，UI 任务还要对着原型和带编号规格逐页逐状态看截图。

核查面：

- 正确性（对照任务书与定稿，不对照「更常见的开源惯例」）
- 运行时风险（Fatal、钩子时机、断网、镜像故障）
- 数据边界（§7.1-1 自采字段、reroute §5 不进库、凭据）
- 多站点（网络 option、每个子站 cron、capability）
- 向后兼容（3.9.x 回滚、不写 `wp_china_yes`）
- 测试质量（断言是否真能失败）
- CI（是否只在文档里许诺、workflow 没改）
- 阻断项三分类：**阻断** / **建议** / **有意不改**（有意不改必须引用定稿或任务书）

## 代理常见偏差与对策

| 偏差 | 为什么错 | 对策 |
|------|----------|------|
| 按境外隐私惯例改产品默认值：给兼容性报告加「遥测开关」「匿名数据开关」、写成 opt-in、默认关 | 违反定稿 §7.1-1：报告常开、无开关、界面不露出 | 对照 §7.1 表，不要对照 GDPR 博客 |
| 用「隐藏 section」代替删除已删功能 | 违反 ADR-001 | 从注册、schema、迁移、宣传删除 |
| 删了开关后写替代用户文案（「匿名统计」等） | 违反定稿 §7.2：不写替代文案 | 界面不出现该概念；法务句只在 wpcy.com `/privacy-policy` |
| 往 `framework/` 加字段或 Adapter | 4.0 物理删除旧框架，不做封装 | 新代码只进 `src/` |
| 直写 weixiaoduo.com / 其它商业域 | 定稿 §5 / §10：插件只知道 `https://wpcy.com/go/…` | 一律中转层 |
| 在前端或模块里写死套餐 / 额度 | §7.1c：客户端只执行 entitlement | 配额用尽降级回上游 |
| 云桥无入库接口就改 Tracker / Tracks URL | 改道政策 §2 / §6 | 只记录或不改 |
| 广告拦截藏核心更新 / 安全 / 站点健康通知 | §7.1-3 铁律 | 只藏规则表里的第三方推广；诊断页可查 |
| 把 4.0 方案 §6 托管 CDN 当首发 | §7.1-5 / §7.3 后置 | 合同可留，代码不领 |
| 无验收输出声称完成 | 本协议 | 报告贴命令输出 |
| 自审替代独立核查 | 审查角色 | 换一个代理、只读 |

## 统筹写任务书的教训（2026-09-03/04 十路任务实录）

来自首批十个 Grok 任务（3.9.3 审查、M0 文档、wpcy-site、token、原型、任务书起草、脚手架）的验收记录。写任务书的人先读这段。

| 教训 | 实例 | 做法 |
|------|------|------|
| **给原文，不给范围** | token 任务书只写「medium 18–20px」，代理只能按公式推算 clamp()，值不是现网的 | 凡是要抄录的值（CSS、JSON、枚举、字段名），任务书里贴原文；代理复制，不推导 |
| **禁区别划过严** | 4.0 方案回写任务禁改「工程章节」，结果四处旧口径残留，代理主动列出但不敢改 | 禁区写「不改实质决定」，允许改与新决定冲突的旧句；或明确列出允许改的句子 |
| **任务书和上游文档不一致时，代理会按任务书做并报告** | `/go/` 在方案里写 301、任务书写 302 | 这是对的行为。统筹收到报告后改上游文档，不改代理产物 |
| **「没做 / 做不到 / 有疑问」是报告里最值钱的一节** | 每个任务都在这里暴露了任务书或规格的缺口（weavatar 枚举、`plat-api` 是否受 git 管理、并行组依赖矛盾） | 验收先读这一节，再看 diff；空的这一节本身可疑 |
| **枚举值必须来自代码，不来自记忆** | 统筹在 spec 里凭印象写 Windfonts subset 为 sc/tc/latin，真实 API 是 full/zh/zh-common/en | 写 spec 前 grep 现有实现 |
| **任务书外的新文件不一定越界** | 脚手架任务多出 `autoload-guard.php`：不加它 lint/analyse/test 在无 WordPress 的 CLI 下静默退出 0、整套门禁假绿 | 验收时看代理给的理由是否指向一个可复现的真问题；是则接受并记录，不是则打回 |
| **独立核查要换代理、只读、带具体问题清单** | 3.9.3 审查找到 `readme.txt` 漏改、`has_block()` WP 4.9 缺失、`count_users()` 双跑、smoke 断言假通过 | 问题清单按「正确性 / 运行时 / 数据边界 / 多站点 / 兼容 / 测试质量 / CI / 阻断三分类」给 |
| **并发启动用独立命令** | 用 `&` 在一条 shell 里起两路，外层 shell 结束时子进程被回收 | 每路一条后台命令 |
| **权限模式** | `--permission-mode plan` 只出计划不执行；`--deny 'MultiEdit(*)'` 是未知工具名会直接报错退出 | 读写任务用 `--always-approve` + `--deny 'Bash(git push:*)'` 等；只读审查再加 `--deny 'Edit(*)' --deny 'Write(*)'` |
| **报告只在最后一次性输出** | plain 输出模式下中途文件只有一两行，容易误判「卡住」 | 看 worktree 里 `git status` 与会话 events 判断进度，不看报告字节数 |
| **合并后的 `main` 必须重跑门禁，分支各自绿不等于合起来绿** | M1-02 与 M1-03 各自 CI 绿，合并后 `quality` 红：测试替身类靠 PSR-4 根映射 `./` 解析，macOS 不分大小写能找到 `tests/`，Linux CI 找不到 | 合并后在 `main` 跑 `composer check`；`composer.json` 加 `autoload-dev`；写测试替身类必须能被 `autoload-dev` 解析 |
| **别用脚本重写整份 JSON** | 统筹用 Python 重写 `composer.json`，缩进从制表符变空格，下一次合并整文件冲突 | 用保留格式的方式改一处；改完 `git diff` 看是否只有目标行变 |
