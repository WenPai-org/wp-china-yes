## 任务书模板

每个任务必须有这些块；缺一块就停，不要猜：

```markdown
# 任务：<短名>

## 目标
一句话。

## 背景与上下文文件
路径列表（仓内 + `.grok-context/`）。不要联网补资料。

## 交付物
路径级。新建 / 只改哪些。

## 行为规格
对照的 spec / ADR / 定稿条目。

## 禁区
路径、产品决定、文案、git 操作。

## 验收标准
可执行的命令（不只「通过」）。

## 报告格式
见下节。
```

执行者不是决策者：任务书写死的范围、命名、禁区不得自行更改。任务书矛盾或做不到 → **停下来在最终报告里写明**，不要绕。

## worktree 与分支

- 每任务一个独立 git worktree，只在该目录改文件
- 分支：`grok/<topic>` 或 `codex/<topic>`，基于任务书给出的 commit
- 可以 `git add` / `git commit`；**禁止** `git push`、切分支、`git reset --hard`、改 `master`/`main`
- 不要把 `.grok-context/` 提交进 git
- 由审批者合并；代理不发版、不打生产 tag（除非任务书写明授权）

## 报告格式

完成后输出中文最终报告，必须含：

1. 改了哪些文件（`git diff --stat` 原样贴出）
2. 每条验收标准的实际执行命令和输出摘要（不要只写「通过」）
3. 任务书里没做、做不到、或有疑问的项，逐条原因
4. 提交哈希（`git log --oneline -5`）

无命令输出支撑的「完成」视为未完成。审批者会先跑验收命令再看 diff。

## 独立核查

另一个代理 **只读** 审查，不接同一份「再改一版让它绿」的指令混进执行会话。核查面：

- 正确性（对照任务书与定稿，不对照「更常见的开源惯例」）
- 运行时风险（Fatal、钩子时机、断网、镜像故障）
- 数据边界（§7.1-1 自采字段、reroute §5 不进库、凭据）
- 多站点（网络 option、每个子站 cron、capability）
- 向后兼容（3.9.x 回滚、不写 `wp_china_yes`）
- 测试质量（断言是否真能失败）
- CI（是否只在文档里许诺、workflow 没改）
- 阻断项三分类：**阻断** / **建议** / **有意不改**（有意不改必须引用定稿或任务书）

## 代理常见偏差与对策

| 偏差 | 为什么错 | 对策 |
|------|----------|------|
| 按境外隐私惯例改产品默认值：给兼容性报告加「遥测开关」「匿名数据开关」、写成 opt-in、默认关 | 违反定稿 §7.1-1：报告常开、无开关、界面不露出 | 对照 §7.1 表，不要对照 GDPR 博客 |
| 用「隐藏 section」代替删除已删功能 | 违反 ADR-001 | 从注册、schema、迁移、宣传删除 |
| 删了开关后写替代用户文案（「匿名统计」等） | 违反定稿 §7.2：不写替代文案 | 界面不出现该概念；法务句只在 wpcy.com `/privacy-policy` |
| 往 `framework/` 加字段或 Adapter | 4.0 物理删除旧框架，不做封装 | 新代码只进 `src/` |
| 直写 weixiaoduo.com / 其它商业域 | 定稿 §5 / §10：插件只知道 `https://wpcy.com/go/…` | 一律中转层 |
| 在前端或模块里写死套餐 / 额度 | §7.1c：客户端只执行 entitlement | 配额用尽降级回上游 |
| 云桥无入库接口就改 Tracker / Tracks URL | 改道政策 §2 / §6 | 只记录或不改 |
| 广告拦截藏核心更新 / 安全 / 站点健康通知 | §7.1-3 铁律 | 只藏规则表里的第三方推广；诊断页可查 |
| 把 4.0 方案 §6 托管 CDN 当首发 | §7.1-5 / §7.3 后置 | 合同可留，代码不领 |
| 无验收输出声称完成 | 本协议 | 报告贴命令输出 |
| 自审替代独立核查 | 审查角色 | 换一个代理、只读 |
