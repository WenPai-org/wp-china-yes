## 1. 设计立场

1. **叶子在后台里是基础设施，不是应用。** 装上就该少打扰：国内站的界面越少越好；跨境站才需要控制台感。同一套组件，两种密度，由站点场景决定。
2. **说价值，不说配置。** 概览回答"它为我做了什么"（次数、节省、事件），配置状态留给设置页。
3. **每个界面只有一个下一步。** 一页最多一条"下一步"提示；一页只有一个主按钮。
4. **和 WordPress 后台放在一起不违和。** wp-admin 灰阶与系统字体栈；品牌只出现在图标块与主色 `#3858e9`；不用 WPCY 品牌绿。
5. **一根侧栏就够。** 插件内导航用页头下的横向标签；不在 wp-admin 左菜单旁再立一根。
6. **降级可见、失败诚实。** 依赖不可用时用注意色条说明发生了什么、影响什么、下一步是什么；不假装成功；不用"暂无数据"。
7. **数字必须有来源。** 概览的每个数字都来自 `/stats`、`/events`、`/diagnostics`；界面不算分、不造分。

## 2. 信息架构

```
文派叶子（wp-admin 顶级菜单，图标：叶子）
├── 概览    ?page=wpcy            Hero · 下一步 · 过去 7 天为你处理 · 线路 / 动态 · 来自文派
├── 设置    ?page=wpcy-connect    站点场景 · 加速与优化（简单）/ 连通性（高级）· 后台体验
├── 服务    ?page=wpcy-services   绑定 · 可用服务 · 小工具
└── 诊断    ?page=wpcy-diagnose   服务器到各源 · 浏览器到各源 · 记录 · 数据与恢复
    (向导)  ?page=wpcy-onboarding 首次安装；不在菜单；4 步
    (恢复)  ?page=wpcy-recovery   服务端渲染；不在菜单
```

- **菜单 slug 不改**（`wpcy-connect` 仍是设置页），只改标签：连接优化 → **设置**，文派服务 → **服务**。命令面板、e2e、文档里的 slug 一律沿用。
- **横向标签**与左菜单四个子项一一对应，同一页两处同时高亮。
- **向导**：首次激活后第一次进入任一叶子页面时跳到 `wpcy-onboarding`（条件：`wpcy_settings` 无 `profile_confirmed_at`，且没有迁移报告）。3.x 升级站**不**跳向导，改在概览给 OV-09 提示。向导可从设置页"重新运行首次设置向导"再进。
- **路由约束**（沿用 ADR-002）：页内子视图只用 hash，不改 `?page=`，不访问 `window.top`；⌘K 命令走 Core 面板，`wp.os?.registerCommand` 存在时额外注册。命令：「打开文派叶子概览」「打开设置」「打开服务」「运行诊断」「进入恢复模式」。
- **两种密度**：`profile=domestic` 时概览不显示"下一步：绑定本站"、资源带无"跨境店工具"组；`crossborder` / `mixed` 显示。除此之外页面结构相同。

## 4. 页面规格

### 4.1 概览 `wpcy`

自上而下：**恢复横幅**（仅恢复模式）→ **Hero** → **下一步条**（仅有事项时，最多一条）→ **过去 7 天为你处理** → **线路 / 动态两栏** → **来自文派** → 页脚。原型：`overview-domestic` / `-crossborder` / `-degraded` / `-empty` / `-recovery` / `-upgraded`。
