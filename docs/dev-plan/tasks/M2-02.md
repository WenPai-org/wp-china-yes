## 行为规格

以 `docs/specs/entitlements.md` 为准，冲突时以 spec 为准并在报告说明。

流程：

1. `POST {WPCY_SERVICES_API}/v1/site-connections` body `{site_url, site_uuid, plugin_version}` → `{challenge_id, challenge_token, expires_at}`。
2. 本地 `binding.status=pending`，写入 `challenge_id`；token 短时存储（option vs transient **待定（M0）**：作者选定并满足「pending 且未过期才能被公开端点读出」，在报告写明）。
3. `GET /wp-json/wpcy/v1/binding/challenge?id=` **公开只读**，仅 pending 且未过期返回 `{challenge_token}`；否则 404 / `wpcy_binding_not_pending`。
4. mock 模拟服务端回站后，`POST {API}/v1/site-connections/{id}/confirm` → 加密存储 credential，`status=bound`，写 `site_hash`、`bound_at`，清空 `challenge_id`。
5. `GET /binding` 返回 `{status, site_hash, bound_at}`，**不含** credential、challenge_token。
6. `DELETE /binding` → `revoked`，清凭据。通知服务端路径 **待定（M0）**；未定前本地撤销即可，不猜 CDN 合同路径。

`site_uuid` 首次启动生成后稳定。写请求幂等键 `Idempotency-Key`。凭据不进导出、日志、REST。过期挑战不响应。

默认：无 `WPCY_SERVICES_API` 覆盖且非测试环境 → 不自动 `start`。测试用常量或 filter 指向 mock。
