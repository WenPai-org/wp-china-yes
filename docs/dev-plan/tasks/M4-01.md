## 行为规格

以影响分析与 `docs/4.0-rewrite-plan.md` §7.1 为准。

引导（推荐形态，变量名可改）：

```php
define( 'CHINA_YES_VERSION', '3.9.3' ); // 版本字符串本任务不动
define( 'CHINA_YES_PLUGIN_FILE', __FILE__ );
// URL / PATH 同现状
if ( file_exists( CHINA_YES_PLUGIN_PATH . 'vendor/autoload.php' ) ) {
    require_once CHINA_YES_PLUGIN_PATH . 'vendor/autoload.php';
    \WenPai\ChinaYes\Core\Plugin::boot();
    return;
}
// 无 autoload：admin notice 后 return（可保留现状文案）
```

首次启动迁移：

- 单站：无 `wpcy_settings`（或等价「尚未迁移」判定）且 `wp_china_yes` 存在 → `Runner::execute()`，写 `wpcy_settings` + `wpcy_migration_backup`。
- 多站点网络：对 `wpcy_network_settings` / `get_site_option('wp_china_yes')` 同样。
- 已有 4.0 option：不覆盖、不重跑。
- 损坏非数组 `wp_china_yes`：按 `LegacyReader` 当空，不 Fatal。
- 永不 `update_option('wp_china_yes', …)`。

`composer.json` 删旧后：

```json
"autoload": {
  "psr-4": { "WenPai\\ChinaYes\\": "src/" }
}
```

`files` 为空。`require` 不再含 `plugin-update-checker`。

## 验收标准

1. `grep -rn "framework/\|Service\\\\\|client/" src/ wp-china-yes.php composer.json` 无输出。（`Services\` 带 s 的 4.0 命名空间允许存在；若本命令因 `Service\\` 命中 `Services\\`，改用 `grep -rn 'framework/\|WenPai\\ChinaYes\\Service\\\|client/'` 并在报告贴两条输出。）
2. `composer check` 全过（已无 `test:legacy`）。贴 phpcs / phpstan / 各 phpunit suite 摘要。
3. `npm run build && bash scripts/build-release.sh`；`unzip -Z1 dist/*.zip | grep -E 'framework/|Service/|client/|templates/|assets/|Plugin.php|helpers.php|autoload-guard.php|yahnis-elsts'` 无输出；含 `wp-china-yes/build/index.js`。
4. e2e 全过（CI `e2e` job 或本地 Studio 等价）。贴命令与末行。
5. Plugin Check 零发现（CI job 或报告中的 JSON/`No errors found`）。
6. `git log --oneline -5` 可见两个 commit；信息前缀 `refactor:` 或 `build:`（删旧用 `refactor:`，打包/CI 用 `build:`）。
7. `git diff --stat` 相对 `main` 不含 `docs/dev-plan/README.md`。
