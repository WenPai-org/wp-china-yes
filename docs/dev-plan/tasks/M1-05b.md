## 背景

M1-02（内核）与 M1-03（配置）并行开发，留下两个接缝：`Repository` 没实现 `Core\Config`，`Plugin::create()` 仍注入空配置。M1-04 / M1-05 / M1-09 三个模块各自可实例化、单测全过，但都没有挂进 `Plugin::create()`，所以 `WPCY_KERNEL=v4` 时什么都不发生。M1-05 按任务书没实现 `weavatar` 改写，而枚举已决定保留（README §4），不实现则迁移过来的 `weavatar` 用户头像加速静默失效。本任务把这些一次收口，使 v4 内核成为**真正能跑的插件**。

独立审查（Grok，2026-09-04）对内核的阻断与建议：
- 阻断：`Repository` 实现 `Core\Config` 并补 `has()`；`create()` 注入真 Repository、删 `null_config()`。（第三项 autoload-dev 已修。）
- 建议：`enabled()` / `dependencies()` / `contexts()` 也纳入失败隔离 try/catch；v4 路径的激活/卸载钩子要么注册要么明确不走 3.x `activate`；`Logger::redact` 处理 `exception` 键并递归嵌套数组；`Repository::get()` 用 `array_key_exists` 区分"无键"与"值为 null"；属性补 PHP 7.4 类型声明。

## 行为规格

- `WPCY_KERNEL=v4` + 默认配置 + admin 场景：`boot('admin')` 后五个模块中 `contexts()` 含 `admin` 且 `enabled()` 为真的都已 `register()`；任一模块抛异常不影响其它。
- `Repository::has('connectivity.avatar')` 为真；`has('nope.nope')` 为假；`get('x', 'fb')` 在键存在且值为 `null` 时返回 `null`。
- `weavatar`：`connectivity.avatar = weavatar` 时 Gravatar URL 改写到 3.x `Service/Avatar.php` 里 `weavatar` 分支所用的主机；`off` 不改写；三档 Cravatar 行为不变。
- v4 停用钩子清 `wpcy_daily_telemetry`；激活钩子不得写 3.x 的 `wp_china_yes`。
- 3.x 路径零变化（`composer test:legacy` 29 仍过；`WPCY_KERNEL` 未定义时 `Core\Plugin` 不被实例化——已有 `KernelSwitchTest` 必须继续通过）。
