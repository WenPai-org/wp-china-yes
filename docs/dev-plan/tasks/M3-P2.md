依赖：**M3-P1** 已合并或提供可装的 4.0 RC ZIP；**M3-S1 / S2 / S3** 生产或指定试点环境就绪。并行组无。预计规模：文档 + 运营 checklist，插件 diff 以观察记录为限（≤ 200 行文档）。基于 `main`。工作分支 `grok/m3-p2`。

## 行为规格（checklist）

每一步写：执行人、时间（UTC ISO 8601）、命令、输出摘要、结果（ok / 跳过+原因 / 失败+回滚）。空白标「待定（M3 前）」。

### 1. 选站

- 候选：wenpaiorg-prod 上的 wenpai.org、wpcy.com、wapuu.com 等自有站（定稿 §9 与 verification 目录为线索，不是授权清单）。
- 排除：客户站、收款/支付主路径未备份的站、无写权限的站。
- 写下：站点 URL、WP 版本、是否 WooCommerce、当前叶子版本（3.x 或未装）、谁授权。
- 未选定就停，不装 RC。

### 2. 备份

- 文件：插件目录、`wp-config.php`（常量）。
- 数据库：全库或至少 `wp_options` / 多站点 sitemeta（含 `wpcy_*`、旧 `wp_china_yes`）。
- 记下备份路径与校验（体积或校验和）。无备份不得进入第 3 步。

### 3. 装 4.0 RC

- 使用 M2-08 / 发布链打出的 ZIP（含 `build/`），或 P1 分支在 **该站** 的授权部署方式。不在生产 `plugin install` 乱源 ZIP。
- 激活后确认 `WPCY_KERNEL=v4`（或 RC 已默认 v4——以当时 `main` 为准，不在本任务改开关语义）。
- `framework/` 在 v4 下零加载（`get_included_files()` 或 P1/M1 已有断言方式）。
- 免费基线（镜像、诊断、恢复页）在未绑定前可用。

### 4. 绑定

- 走自动匿名挑战：插件 → S1 → 回站 `GET /wp-json/wpcy/v1/binding/challenge` → confirm。
- 记录 `site_hash`（可截断）、`bound_at`、**不记录** `credential` / `challenge_token` 明文。
- `GET /wp-json/wpcy/v1/binding` 无凭据字段。

### 5. 看权益

- `GET /wp-json/wpcy/v1/entitlements`（或文派服务页只读）：出现 `wpcy-leaf-motusnap-100`，`quota.limit` 为服务端值（期望 100），`period=month`。
- 不在插件源码搜数字 100 当验收（P1 不应写死）。若无权益：停并写 S1 侧原因，不在插件里造一条。

### 6. 看云桥与 ingest

在云桥 admin（设计文档 §4；家宽走系统卡隧道，不把隧道写进插件）：

- `_environment`：该站（或总量）在装 RC 后是否出现 PHP / 平台字段（4.0 发 2.1 全集）。
- `_woocommerce`：若该站无 Woo，记「不适用」；有 Woo 则看是否仍全 0。
- ingest 计数：Tracker / Tracks 在 `enabled_when` 为真后应增加（S2 报告中的观察方法）。无 Woo 则 Tracker 可能为零，须在记录区分「无来源」与「改道失败」。
- 抽查不得出现政策 §5「不进库」类（评论正文、许可密钥、管理员 IP）。只读查询。

A 档：`GET /ingest/health` 为 `{ready:true,…}` 之后，该站出站 `tracking.woocommerce.com` 应改打 `updates.wenpai.net`。用诊断页或服务器出站日志证明；不得 tcpdump 客户机密码。

### 7. 七天回看

从绑定日（UTC）起满 7×24h 后再填本段，不得提前勾「完成」。

- 绑定是否仍 `bound`。
- 权益 `used` 是否单调不减、是否在 `limit` 内；`resets_at` 是否合理。
- ingest 计数 7 日点（至少 D0 / D3 / D7）。
- 站点前台 / 结账（若有 Woo）无因改道导致的功能失败。若失败：立即走第 8 步。
- 云桥决策台无因本站产生的脏 UA 当 WP 版本（已知历史问题，本任务只观察，不修 parser，除非阻断试点）。

### 8. 回滚路径

装 RC 前写进记录，失败时按序执行：

1. 插件恢复页 `?page=wpcy-recovery`：关全部改写与模块（无 JS）。
2. 停用 4.0，恢复第 2 步的插件文件备份（3.9.x 或原版本）。
3. 需要时恢复 options（迁移回滚若 M2-01 已执行过）。
4. 确认前台 200、结账可用、叶子 3.x 更新检查仍走原通道。
5. 通知 S1：本地 `revoked` 后是否调撤销端点——路径若仍「待定（M3 前）」则只本地撤销，并记一笔。

回滚本身也要在 verification 文件写命令输出。未演练的回滚视为未完成第 8 步；至少在 staging 或本站做过第 1 条恢复页。

## 验收标准

本任务的「通过」= verification 文件里每步有命令或明确跳过原因。审批者按文件复跑只读项。

1. 记录文件存在且八步都有结果行：

```bash
ls docs/dev-plan/verification/m3-p2-*.md
grep -n "^### [1-8]\." docs/dev-plan/verification/m3-p2-*.md
# 期望：恰好一篇（或按站一篇）含 1–8 节。
```

2. 绑定只读证明（在试点站执行，审批者持有授权时）：

```bash
# HOME 为该站 URL。须 manage 会话或应用密码，不把密钥写进 git。
curl -sS "$HOME/wp-json/wpcy/v1/binding"
# 期望：status=bound；JSON 无 credential、无 challenge_token。
```

3. 权益：

```bash
curl -sS "$HOME/wp-json/wpcy/v1/entitlements"
# 期望：id=wpcy-leaf-motusnap-100；quota.period=month。
```

4. 健康端点（只读）：

```bash
curl -sS "https://updates.wenpai.net/ingest/health"
# 期望：ready true（家宽不通则按系统卡隧道，在记录写访问方式）。
```

5. 七天：记录含 D0/D3/D7 三个时间戳与 ingest 或「无 Woo、Tracker 零」的书面区分。日期差 ≥ 7 天。

```bash
grep -n "D0\|D3\|D7\|bound_at\|ingest" docs/dev-plan/verification/m3-p2-*.md | head -40
```

6. `git diff --stat` 仅 verification 文档（及本任务书不在此 diff）。不得改 `src/`、`framework/`、`Service/`、`client/`。

7. 提交信息前缀 `docs(verify): `（观察记录）或本任务书之外无代码提交。

8. `composer test:legacy` 若本仓有代码改动才跑；仅文档则跳过并在报告声明。
