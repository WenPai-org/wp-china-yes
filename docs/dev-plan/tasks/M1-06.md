## 交付物

| 路径 | 职责 |
|------|------|
| `src/Diagnostics/DiagnosticsModule.php` | id `diagnostics`；定时检查（`diagnostics.scheduled_checks`） |
| `src/Diagnostics/Checker.php` | 对 WordPress.org 镜像、公共库节点、头像线路发探测，记录目标、结果、延迟、最近检查、建议 |
| `src/Diagnostics/SiteHealth.php` | 注册 Site Health 段（只展示连接状态，不含凭据） |
| `src/Cli/StatusCommand.php` | `wp wpcy status` |
| `src/Cli/DoctorCommand.php` | `wp wpcy doctor` |
| `src/Cli/ConfigCommand.php` | `wp wpcy config export` / `import`（export 剥凭据） |
| `tests/Unit/Diagnostics/CheckerTest.php` | 结果对象字段 |
| `tests/Integration/CliTest.php` 或 wp-env 脚本 | CLI JSON schema；Site Health 段出现 |

WP-CLI 注册方式：`WP_CLI::add_command`，仅 `cli` 场景。cdn purge **不在**本任务（4.x CDN）。

## 行为规格

以 `docs/specs/rest-api.md` `/diagnostics` 摘要与 `docs/design/admin-ui-spec.md` §3.4、§4 词表为准，冲突时以 spec 为准并在报告说明。

结果对象（REST 将原样返回；字段名本任务冻结，M1-07 不另发明）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `target` | string | 人读名，如 `downloads.wenpai.net` / `cdnjs.admincdn.com` |
| `result` | string | `ok` \| `fallback` \| `down`（界面映射：国内镜像正常 / 已回原始上游 / 不可用） |
| `latency_ms` | int \| null | 探测耗时 |
| `checked_at` | string | UTC ISO 8601 |
| `suggestion` | string \| null | 仅异常时有；正常为 null |

**待定（M0）**：完整 JSON schema 由本任务作者补进 `docs/specs/rest-api.md` 或独立附件——允许本任务**追加**该 schema 段到 `docs/specs/rest-api.md` 的 `/diagnostics` 小节，不得改其它端点。若任务书「只新建 tasks/*.md」与「补 schema」冲突：本任务书范围是 4.0 代码任务，**执行 M1-06 时代码仓允许改 spec 该小节**；起草本任务书时不改 spec。

`wp wpcy status`：stdout JSON，含 kernel 开关、recovery_mode、各 target 最近结果。`wp wpcy doctor`：跑一轮检查并打印同上。`config export`：`wpcy_settings`（及网络 option），**无** `wpcy_site_identity.binding.credential`。`config import`：经 Validator，未知键丢弃。

Site Health：一段「文派叶子」debug 信息，字段同结果对象摘要。不出现「遥测」字样。

失败诚实：远程失败不得显示成功（`docs/dev/testing.md` 门禁）。

## 与 3.x 的关系

- 3.x 无等价 CLI。`Service/Monitor.php` 的 cravatar 探测**不**作为 4.0 诊断合同；可参考超时与 URL，不移植监控 UI。
- 无必须保留的 3.x 测试名。legacy 29 必过。

## 禁区

- 总计划 §0；不改 3.x 运行时。
- 不实现 REST 路由（M1-07）。不实现恢复页。
- 导出不得含凭据、订单正文、邮箱。
- 禁止「遥测开关」、opt-in、「默认关闭」文案（反例）。
- 不写 `wp wpcy cdn purge`（4.x）。

## 验收标准

1. `composer check` 全过。
2. wp-env：`npx wp-env run cli wp wpcy status --format=json` 输出可被 `json_decode` 且含 `targets` 数组；`wp wpcy doctor` 退出码 0 或 1（有 down 时 1 可接受，须在报告写明）。
3. wp-env：Site Health REST 或 `wp eval` 断言文派叶子段存在。
4. `git diff --stat` 限于 `src/Diagnostics/`、`src/Cli/`、对应测试。若补 `docs/specs/rest-api.md` 仅 diagnostics 小节，在报告单独列出。
5. 提交信息前缀 `feat(core): `（诊断属内核可观测性；若执行者认为 `feat(admin):` 更准，停并在报告问统筹，不要自行换前缀表以外的词。本任务指定 `feat(core): `）。
