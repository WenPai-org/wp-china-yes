# 任务 M2-11：桥接来源校验按修订后规格落地（PHP `classify` + 会话令牌）

worktree 分支 `grok/m2-11`，基于 `main`（`c8447af` 之后，M2-10 已合）。预计 diff ≤ 350 行。

## 背景

M2-10 发现：`sandbox` 不含 `allow-same-origin` 时 iframe 为 opaque origin，宿主收到 `event.origin === "null"`，原规格"只接受 `event.origin === entry_url origin`"在真实沙箱下永远不成立。JS 侧 `src/Admin/app/apps/Bridge.js` 已改为以 `event.source` 为身份判据并接受 `"null"`；规格 `docs/specs/apps-manifest-and-bridge.md` §3.1 已于 2026-09-06 修订（**先读它，以它为准**）。本任务把剩余部分落地：

1. **PHP `src/Apps/Bridge.php::classify()`** 仍要求 `origin === entry_origin`，与 JS 不一致。按 §3.1 改为：`origin` 为 `"null"` 或 `entry_origin` 都通过；其它值 `wpcy_apps_origin_mismatch`。`event.source` 是否为 iframe 的判定沿用现有字段。
2. **会话令牌**（§3.1 新增）：
   - 宿主（`Bridge.js`）每次挂载生成 32 字节随机 token（`crypto.getRandomValues` → base64url），放在 `init.payload.session_token`。
   - 工具之后每条消息在信封顶层带 `session_token`；宿主校验不一致/缺失 → 丢弃并（能回时）回 `error`，`code = wpcy_apps_session_invalid`。`ready` 例外。
   - PHP `Bridge.php` 增加常量 `ERR_SESSION_INVALID = 'wpcy_apps_session_invalid'`，`classify()` 接受 `session_token`/`expected_session_token` 字段并做同样判定，保持 PHP 合同与 JS 行为一致（PHP 只是合同镜像，运行时走 JS）。
   - `tests/fixtures/mock-app/index.html` 记住 `init` 里的 token 并在后续消息回带。
   - `docs/specs/apps-manifest-and-bridge.md` §3.2 消息表 `init` 行与 §5 错误码表已改；如工具侧 SDK 示例段落存在，补 token 用法。
3. **合同测试**（`tests/Unit/Apps/BridgeContractTest.php`）新增用例：`"null"` origin 通过；陌生 origin 拒绝；token 缺失拒绝；token 错误拒绝；`ready` 无 token 通过；"同一 `event.source`、`origin` 变为第三方站、无 token" 拒绝（模拟工具页自行导航）。
4. **e2e**（`tests/e2e/apps.spec.js`）：A5 继续通过；新增一条 A10：mock 工具发一条带错误 token 的 `data.set`，断言宿主 `#log` 出现 `session_invalid`（mock 工具需要一个触发按钮或 URL 参数）。
