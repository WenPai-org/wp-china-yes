## 背景

A 档纯上报（Woo Tracker、Tracks）要挡出国并在国内给出客户端能接受的成功应答。叶子只改目的地；**哪些字段进库以政策 §5 为准**，在云桥入库层筛，不在插件筛。

没有本任务的入库接口，叶子改 URL 等于把周报打进 404。健康端点是插件 `enabled_when=ingest_ready` 的唯一门禁：探测为真才改写。

## 交付物

全部落在 `WenPai-org/wenpai-bridge`（及系统卡 / 部署文档）。本产品仓零服务端代码。

| 交付 | 职责 |
|------|------|
| Tracker ingest | 接收原打向 `tracking.woocommerce.com` 的周报；筛字段后入库；返回客户端可接受的成功应答 |
| Tracks ingest | 接收原打向 `pixel.wp.com` / `stats.wp.com` 的埋点；同样筛选 + 成功应答。路径 **待定（M3 前）**：对照该仓已有 `/ingest/woo-tracker` 风格在报告提出，**不得自行改产品仓 spec**；统筹回写后再给 P1 |
| 健康端点 | `GET /ingest/health` → `{ "ready": true, "targets": [ … ] }` |
| 现网应答 fixtures | 先抓 `tracking.woocommerce.com` 与 `pixel.wp.com` 真实成功响应，存该仓 fixtures，再定本服务应答体 |
| 合同测试 | 必留字段进库；不进库字段不出现；健康端点 JSON |

插件基线里 Woo Tracker `target` 已是 `https://updates.wenpai.net/ingest/woo-tracker`。Tracks `target` 在产品仓仍为空字符串（M1-09 占位）。

## 行为规格

以 `.grok-context/wenpai-leaf-telemetry-reroute.md` 为准，冲突时以该政策为准并在报告说明。空白标「待定（M3 前）」。

### 改道，不是镜像（政策 §2）

- 原厂收不到：成功应答由本服务给出。
- 禁止抄一份给云桥再放行原请求。
- 响应体政策原句：**「对照现网 `tracking.woocommerce.com` / `pixel.wp.com` 再定」。** 执行者必须先抓一次真实响应形态作为 fixture，再实现本服务应答；未抓到不得编造 body。抓取范围仅限公开成功应答（状态码、Content-Type、body 形状），不抓业务密钥。

### 本任务范围（A 档）

| 原主机 | 用途 | 本任务 |
|--------|------|--------|
| `tracking.woocommerce.com` | Woo Tracker 周报 | ingest + 筛选 + 成功应答 |
| `pixel.wp.com` / `stats.wp.com` | Tracks 埋点 | 同上 |
| `api.wordpress.org` version/update-check | 核心/插件/主题更新检查 | **不做**（已由 Connectivity / 现有云桥 `update-check` 承担） |

B 档（Akismet comment-check、Jetpack 连接、Woo.com helper、Freemius/EDD）本任务**不改道**。C 档不碰。

### 入库筛选（政策 §5，严格执行）

筛选在云桥入库层。叶子不改字段。

**必留（运营项）**

版本、插件清单、环境、货币、国家、HPOS、网关名、是否开追踪。`.org` 更新检查和 2.1 健康上报已经有一部分；Tracker 周报会再带来一层。

**改道后留国内（Tracker 多出来的一层）**

管理员邮箱、订单金额（GMV 合计、按网关拆金额）。旧句「因同意书 / 隐私所以不收邮箱和金额」作废。

**不进库**

| 类 | 例子 |
|----|------|
| 评论与顾客联系 | 评论正文、作者、顾客邮箱/电话；Akismet 评论包 |
| 功能密钥 | 许可密钥、Jetpack 握手、Woo.com helper token |
| 精确地理 | 管理员 IP、经纬度、商店省/州、邮编 |
| 订单正文 | 近 20 单抽样（行项目、顾客侧内容） |
| Automattic 侧身份 | `store_id`、Jetpack `blog_id` |
| 凭据与正文 | 用户密码、文章正文 |

`site_url` 明文入库是国内合规需要（云桥数据模型已按明文设计）。

覆盖页口径（政策 §6）：邮箱和金额是 `gap` 不是 `refuse`；本任务把 gap 补上。`refuse` 永不入库。

### 健康端点

```
GET /ingest/health
```

就绪时：

```json
{
  "ready": true,
  "targets": ["woo-tracker"]
}
```

- HTTP 200 且 `ready === true` 时，插件才把对应 A 档 `reroute` 打开。
- `targets` 列出已具备筛选入库 + 成功应答的 ingest 名。Woo Tracker 用 `woo-tracker`（与路径 `/ingest/woo-tracker` 对应）。Tracks 名 **待定（M3 前）**，以本任务报告为准。
- 未就绪：`ready: false` 或非 200。插件不得改写。
- 与现有 `GET /healthz` 分工：`/healthz` 是进程/DB/队列；`/ingest/health` 只回答「A 档替代应答是否就位」。不要把两者合成一个语义。

### 现有 API 面（只增不拆）

公开面已有 `POST /api/v1/update-check`、`POST /api/v1/telemetry`、`GET /healthz` 等（设计文档 §4）。本任务增加 ingest 与 `/ingest/health`，**不改**既有 telemetry 2.1 合同，不把 Tracker 周报塞进 `/api/v1/telemetry`。

Admin `_environment` / `_woocommerce` 继续给 **M3-P2** 观察用；本任务若入库新表，须让既有 admin 计数能看到 ingest 次数或在报告写明观察方法。

### P0 门禁

生产是 P0。`docs/systems/wenpai-bridge/card.json` 在 linuxjoy 仓。

部署流程写死为：**备份 → PR → CI → 文档化部署**。**禁止 UPDATE 活库 `stats.db`。** 禁止在生产容器里手工改库「先看一下」。schema 变更走迁移，在 staging 验证后再进生产。家宽打 `updates.wenpai.net:443` 不通时走系统卡 `network.access`（SSH 隧道），不把临时隧道写进插件。

## 验收标准

在 **wenpai-bridge** 仓与 staging 执行。禁止对生产 `stats.db` 做 UPDATE。

1. 现网应答 fixture 已入仓（至少 Tracker 与 Tracks 各一份），且本服务成功应答的 Content-Type / 状态码与 fixture 对照表写在报告里：

```bash
# 抓取（执行者环境能出网时；只抓成功应答，结果存该仓 fixtures，不提交 Cookie/密钥）
curl -sS -D - -o /tmp/woo-tracker-body.bin "https://tracking.woocommerce.com/" | head
curl -sS -D - -o /tmp/pixel-wp-body.bin "https://pixel.wp.com/" | head
# 期望：报告含 HTTP 状态、Content-Type、body 长度/十六进制或文本摘要；fixtures 路径列入 diff。
```

2. staging ingest 接受一份无「不进库」字段的最小 Tracker 样例，返回成功（对照 fixture 的状态码）：

```bash
curl -sS -D - -X POST "$STAGING_BRIDGE/ingest/woo-tracker" \
  -H "Content-Type: application/json" \
  -d @fixtures/ingest/woo-tracker-min.json
# 期望：成功状态码与 fixture 一致；响应体形状与报告对照表一致。
```

3. 带「不进库」字段的样例入库后查库（staging，只读）不得出现评论正文、顾客电话、许可密钥、IP、邮编、`store_id`、密码：

```bash
# 只读查询；具体 SQL/命令按该仓存储书写。禁止写生产。
# 期望：报告贴查询与空结果 / 被丢弃证明。
```

4. 必留 + 改道后留国内：样例含管理员邮箱与 GMV 合计时，staging 可读出（明文 `site_url` 允许）：

```bash
# 只读。期望：邮箱与金额存在；site_url 明文。
```

5. 健康端点：

```bash
curl -sS "$STAGING_BRIDGE/ingest/health"
# 期望：HTTP 200，JSON 含 "ready": true，且 targets 为数组、含 "woo-tracker"。
python3 -c 'import json,sys; d=json.load(sys.stdin); assert d["ready"] is True; assert "woo-tracker" in d["targets"]' <<<"$(curl -sS "$STAGING_BRIDGE/ingest/health")"
```

6. 现有 `GET /healthz` 仍 200（回归，不改语义）。

7. 部署记录含：备份点、PR 链接、CI 绿、文档化步骤。报告声明 **未** UPDATE 生产 `stats.db`。

8. 本产品仓本次任务 **零 diff**。
