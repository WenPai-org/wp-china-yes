## 行为规格

版本字符串必须三处相同：`Version:`、`CHINA_YES_VERSION`、`package.json` 的 `version`。`sync-version.sh` 已允许 `4.0.0-rc.1` 这类后缀。

4.0 段必须出现的事实（对照定稿 §7.1 / §7.3，不得加减产品范围）：

- 保留：WordPress.org 镜像与回源、公共库、Cravatar、诊断、恢复页、站点绑定与权益客户端、小工具容器、公告、广告拦截（NoticeControl）、Windfonts 可选模块。
- 删除：评论、维护模式、监控、语言分离、媒体 WebP、性能/内存常量、RSS 新闻欢迎营销、飞行模式、白标（不进首发）、托管 CDN（不进首发）。
- 迁移：启用 4.0 后只读 `wp_china_yes` 生成新设置；旧键保留；可停用后装回 3.9.x。
- 最低：WordPress 6.5；PHP 写统筹值或「待定（占位 8.0）」。
- 界面不出现「遥测」「匿名数据」「隐私开关」。兼容性报告若需一笔带过，用既有「兼容性报告」口径，不写开关。

官网草稿：

- `/changelog`：与 `CHANGELOG.md` 4.0 段同事实、可略短。
- `/news`：升级价值 + 删除项预览，给 3.x 站长看。交产品侧；插件内升级提示若尚未有文案槽，本任务不发明 UI。

runbook 复核清单（逐条在报告打勾）：

1. 冻结合入 / 三处版本 / CHANGELOG / CI ZIP / SHA 对 HEAD
2. 4.0 不再走 plat-api；3.9.x 通道不在本任务改
3. 回滚步骤与 M4-02 矩阵一致
4. 代理默认不 tag、不 push `main`、不发 Release

## 验收标准

1. `bash scripts/sync-version.sh 4.0.0-rc.1` 后：
   ```bash
   grep -n "^ \* Version:" wp-china-yes.php
   grep -n "CHINA_YES_VERSION" wp-china-yes.php
   node -e 'console.log(require("./package.json").version)'
   grep -n "Stable tag:" readme.txt
   ```
   三处插件版本与 Stable tag 均为 `4.0.0-rc.1`。
2. `grep -n "Requires at least" wp-china-yes.php readme.txt` 为 6.5。
3. `CHANGELOG.md` 有 `4.0.0-rc.1` 段；「未发布」仍在。
4. `test -f languages/wp-china-yes.pot`。
5. 官网两份草稿文首含「交产品侧」。
6. `composer check` 全过（版本字符串测试若钉死 3.9.3，改为 rc.1）。
