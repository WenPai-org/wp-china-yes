## 行为规格

以 `docs/specs/rest-api.md` 为准，冲突时以 spec 为准并在报告说明。

**本任务端点表（摘自 spec）：**

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET / PUT | `/settings` | `manage_options` | 完整 `wpcy_settings`；PUT 经 schema；未知键丢弃 warning |
| GET / PUT | `/network-settings` | `manage_network_options` | 完整网络对象 |
| GET | `/diagnostics` | `manage_options` | 最近一次检查（M1-06 对象） |
| POST | `/diagnostics/run` | 同上 | 触发检查并返回 |
| POST | `/recovery` | 同上 | body `{ "action": "disable_rewrites" \| "disable_modules" \| "exit" }` |

通用：写请求 `X-WP-Nonce`；响应 `X-WPCY-Request-Id`；时间 UTC ISO 8601；错误 `{ code, message, data.status, data.request_id }`，前缀 `wpcy_`。

schema 失败 → `wpcy_invalid_schema` HTTP 400。能力不足 / nonce 无效 → `wpcy_forbidden` 403。未知 recovery action → `wpcy_recovery_unknown_action` 400。

**`/recovery` 动作（spec 原文）：**

| action | 行为 |
|--------|------|
| `disable_rewrites` | 关闭全部 URL 改写，并置 `recovery_mode = true` |
| `disable_modules` | 停用全部可选模块，并置 `recovery_mode = true` |
| `exit` | `recovery_mode = false`。退出后是否自动恢复此前关闭的改写 / 模块 **待定（M0，产品 feibisi）**；未定前**不得自行恢复，只清标志** |

不含 `binding.credential`。不另开 `/site-overrides` 端点（**待定（M0）** 是否需要，本任务不做）。

**恢复页（`docs/design/admin-ui-spec.md` §3.5 + ADR-002）：**

- PHP `add_menu_page` / `add_submenu_page`，`parent=null` 隐藏于菜单，直连 `?page=wpcy-recovery` 可达。
- WP 原生 `wrap`：`<h1>`「文派叶子 · 恢复模式」；说明「如果后台样式错乱或站点无法访问，可在此一键停用所有 URL 改写与模块。此页不依赖 JavaScript。」
- 两按钮，各自 nonce：`button-primary`「关闭全部 URL 改写」；`button-secondary`「停用全部模块」。对应前两个 action，**不走 REST**（表单 POST）。
- 已在恢复模式：绿色 Notice「恢复模式已开启」+「退出恢复模式」。页底「返回概览」。禁止其它设置。
- 权限 `manage_options`。无 JS 可用。

## 禁区

- 总计划 §0；不改 3.x 运行时。

## 验收标准

1. `composer check` 全过。
2. unit：无 `manage_options` 的 GET `/settings` → 403；坏 nonce PUT → 403；未知键 PUT 被丢弃且 200 返回无该键；非法 recovery action → `wpcy_recovery_unknown_action`。
3. wp-env：禁用脚本前提下 POST 恢复页表单后 `wp option get wpcy_settings --format=json` 含 `"recovery_mode":true`。
4. `git diff --stat` 限于 `src/Rest/`、`src/Admin/RecoveryPage.php`（及 Admin 下必要的 PHP 菜单注册）、对应测试。
5. 提交信息前缀 `feat(admin): `。
