## 行为规格

### `index.json` 签发与托管

形状（摘 spec §2）：

```json
{
  "schema_version": 1,
  "generated_at": "2026-09-03T12:00:00Z",
  "apps": [ "<manifest>…" ],
  "signature": "…"
}
```

- 索引签名覆盖去掉 `signature` 后的规范化 JSON（规则同 spec §1.3）。`kid` 为 `wpcy-apps-2026`。
- 单个 manifest 同样规范化 + Ed25519；`entitlement` 为 `wpcy-leaf-motusnap-100` 的工具（MotuSnap）若进首发索引，字段按 spec §1.1。首发索引里放哪些工具 **待定（M3 前）**（至少须能被 P1 真实拉取并验签；可先放一份最小已签名列表，甚至空 `apps: []` 只要整份验签通过——若空列表，在报告标明，供 P1 用「验签通过但无工具」作验收）。
- **私钥不在 wpcy.com。** 签发在 license-server 的签名服务（S1）。本任务脚本：读未签名 JSON → 调内部签发 → 得到 `signature` → 上传静态托管。CI 密钥只持有调用内部接口的凭证，不持有 Ed25519 私钥文件。
- 来源白名单：初始主机 `apps.wpcy.com`；`entry_url` 必须 HTTPS，后缀 ∈ `.wpcy.com` / `.wenpai.net`。
- 插件每日拉一次、24h transient（插件侧 M2-04 / P1）；本任务保证 URL 稳定、HTTPS、CORS **待定（M3 前）**：若浏览器直接拉才需要 CORS；插件 `wp_remote_get` 不需要。未定前按「仅服务端拉」处理。

### 公告聚合

插件源：`GET https://wpcy.com/wp-json/wpcy/v1/announcements`。

本任务（wpcy-site 插件）：

1. 拉取 wptea.com 与 one.weixiaoduo.com 的 feed（具体 feed URL **待定（M3 前）**：对照现网公开 feed，在报告写明；插件仓 `wp-china-yes` **不**直连这两站）。
2. 清洗：纯文本 title、HTTPS url、summary ≤ 200 字、稳定 `id`、`source` ∈ `wptea` | `one`、`published_at` UTC ISO 8601。丢弃非 HTTPS、无 title、无法稳定 id 的条目。
3. 缓存 **1h**（聚合侧；插件侧另有 24h transient）。
4. 输出最多 20 条，按 `published_at` 新到旧。
5. 失败：返回上一份缓存；无缓存时形状仍合法（`items: []`），不 5xx 糊弄。

```json
{
  "generated_at": "2026-09-03T12:00:00Z",
  "items": [
    {
      "id": "wptea-12345",
      "source": "wptea",
      "title": "…",
      "url": "https://wptea.com/…",
      "summary": "…",
      "published_at": "2026-09-03T08:00:00Z"
    }
  ]
}
```

不可加源。无营销弹窗（这是插件 UI 约束；本端点不返回弹窗指令）。

## 验收标准

在 linuxjoy 仓 / staging 或 wenpaiorg-prod 只读探测（写操作走 PR，不直接改生产主题）。

1. `index.json` 可拉且含 `signature`、`schema_version`、`apps`：

```bash
curl -sS "https://apps.wpcy.com/index.json" | python3 -c 'import json,sys; d=json.load(sys.stdin); assert d["schema_version"]==1; assert "signature" in d and "apps" in d; print("apps", len(d["apps"]), "sig_len", len(d["signature"]))'
# staging 用报告中的 staging 静态 URL 替换。期望：合法 JSON，签名非空。
```

2. 验签（用 P1 将入包的公钥或本任务公布的 staging 公钥；私钥不出现）：

```bash
# 执行者用与 spec §1.3 相同的规范化后 sodium 验签。
# 期望：verified=true。改 apps[0] 任一字节后失败（若 apps 为空则改 generated_at）。
```

3. 签发脚本不在 wpcy.com 主机上读 `*.key` / pem：

```bash
# 在签发脚本与 CI workflow 上：
grep -nE "ed25519|private.key|\.pem" <签发脚本路径> || true
# 期望：无私钥文件路径；只有对 S1 内部接口的调用。报告贴脚本相关行。
```

4. 公告端点形状：

```bash
curl -sS "https://wpcy.com/wp-json/wpcy/v1/announcements" | python3 -c 'import json,sys
d=json.load(sys.stdin)
assert "generated_at" in d and "items" in d
assert len(d["items"])<=20
for it in d["items"]:
    assert it["source"] in ("wptea","one")
    assert it["url"].startswith("https://")
    assert len(it["summary"])<=200
print("n", len(d["items"]))'
# staging 替换主机。期望：字段齐全；源仅为 wptea|one。
```

5. 聚合缓存 1h：连续两次 `curl` 的 `generated_at` 相同（一秒内）；报告可用响应头或两次 JSON 证明。强制刷新方法 **待定（M3 前）**，未定则只测自然缓存。

6. 广告规则 JSON 含版本字段；fixture / 生产规则不含 core / `update-nag` / Site Health 选择器：

```bash
python3 -c 'import json,sys,re
p=sys.argv[1]; d=json.load(open(p)); s=json.dumps(d)
assert re.search(r"version", s, re.I)
for bad in ("update-nag","site-health","update_nag"):
    assert bad not in s.lower()
print("ok", p)' <规则文件>
```
