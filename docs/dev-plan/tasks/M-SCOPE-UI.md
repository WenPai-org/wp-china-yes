# M-SCOPE-UI：站点场景与作用域 — 原型 / 规格需求说明

这份文档**不是任务书**。它给原型 C 与后续 M-UI 任务提供状态清单和文案原文。产品化 UI 必须走 [`docs/dev/design-sop.md`](../../dev/design-sop.md) 门禁：每个状态有 HTML、文案是原文、feibisi 书面认可后才能拆 M-UI 任务写代码。

## 解决什么问题

向导第一步、概览确认提示、连接优化页作用域呈现，需要在写代码前冻结状态与词表。本文件把 [ADR-004](../../architecture/adr-004-site-profile-and-scope.md) 的界面面列成可画的状态，供原型 C 定稿后并入 M-UI。

## 不做什么

- 不写视觉、不写布局、不定色值与间距（那是原型的事）。
- 不改 `src/`、不改 `src/Admin/app/`、不拆 M-UI 任务书。
- 不发明 §4 词表以外的用户可见句子。
- 不把本文件当成已认可的 UI 任务书（无 `APPROVAL.md` 则 M-UI 任务书无效）。

依据：ADR-004；[`docs/design/admin-ui-spec.md`](../../design/admin-ui-spec.md) §2 场景条目、§4 词表；规格编号 `WZ-01` / `OV-09` / `CO-07`；REST [`docs/specs/rest-api.md`](../../specs/rest-api.md) `GET /profile/suggest`、`GET/PUT /settings`。

引擎（Schema、门控、建议接口）由 [M-SCOPE-1](M-SCOPE-1.md) 交付。本文件假设那份已合，或与原型并行时以 mock 该 REST 为准。

## 1. 向导第一步（WZ-01）

非菜单页。首次安装。第一步就是选场景；插件给建议，用户确认。不自动切换。

### 文案（§4 原文）

| 用途 | 原文 |
|------|------|
| 选项 | 国内站 |
| 选项 | 跨境 / 外贸站 |
| 选项 | 混合站 |
| 步骤意图（规格已有，§4 未单列长句） | 用选项本身；不要另写营销句。若原型需要页标题，用「确认你的站点场景」（词表已有） |

不要写「我们检测了你的 IP」。不要展示 IP。

### 状态

| 状态 | 界面要什么 | 数据 |
|------|------------|------|
| 加载 | 三个选项可点；建议尚未出现（不写英文 Spinner 文案；空着或沿用 wp-admin 等待，不新增词） | `GET /profile/suggest` 进行中 |
| 有建议 | 三个选项；建议项可被标明为当前建议（视觉由原型定）。用户可改选后确认 | `suggestion` 为 `domestic` 或 `crossborder` |
| 无建议 | 三个选项，无「建议」标记，用户必须自己选 | `suggestion` 为 `null`（geo 失败、其它 D4 分支、或 `mixed` 不会被建议） |
| 错误 | 与无建议相同（端点 403 / 网络失败不得弹出英文 `WP_Error`） | 当无建议 |
| 确认 | 写入所选 `profile`，并 `apply_defaults`（引擎侧；界面只 PUT） | `PUT /settings` |
| 多站点 | 网络管理员选的是网络策略 `profile`；子站向导若发生，受 `allow_site_override` 约束。原型画网络管理员一条即可 |

`mixed` 只出现在用户手选，不出现在建议。

## 2. 概览确认提示（OV-09）

升级站（3.x → 4.0）未选场景前视为 `domestic`，概览一条提示，**不打断**（不是模态、不是强制向导）。

### 文案（§4 原文）

「确认你的站点场景」

动作按钮若需要，原型用「确认你的站点场景」本身作入口文字，点进向导或连接优化改 `profile`。不要写「你的站点可能在海外」。

### 状态

| 状态 | 是否渲染 | 条件 |
|------|----------|------|
| 需确认 | 渲染该提示 | 来源是 3.x 升级（存在迁移备份 / 报告）且用户从未 PUT 过 `profile` |
| 已确认 / 新装走完向导 | 整段不渲染 | 向导已选，或设置里保存过 `profile` |
| 恢复模式 | 本提示不是恢复横幅。恢复横幅仍是 OV-01。两条可以同时在，提示仍不打断 |

不发明「关闭后永不再现」的 dismiss 键。用户保存场景后自然消失。

## 3. 连接优化页作用域呈现（CO-07）

每项连通性设置旁边呈现作用域。不写布局（不规定在开关左侧还是右侧）。

### 文案（§4 原文）

| 用途 | 原文 |
|------|------|
| scope `admin` | 仅后台 |
| scope `frontend` | 仅前台 |
| scope `both` | 后台与前台 |
| `admin_assets` 预留开关 | 即将提供 |
| 3.x 迁来且 `admin_assets=on` | 后台加速：已保留设置，4.1 起生效 |

`scope=off`：该项关闭，不额外造「已关闭」词（沿用现有关闭态）。

### 按项

| 项 | 作用域怎么呈现 | 备注 |
|----|----------------|------|
| WordPress.org 源 | **不**呈现仅后台 / 仅前台 / 后台与前台 | 服务器侧，无 admin/frontend 之分。控件仍是「自动（推荐）/ 关闭」 |
| 公共前端库 | 呈现三项作用域之一（默认随场景：domestic=`后台与前台`，crossborder/mixed=`仅后台`） | 五项勾选仍在；作用域是整组 |
| 头像 | 不套单一 scope 词。后台一个值、前台一个值（各为 Cravatar 中国 / Cravatar 国际 / 关闭；`weavatar` 按专有名词保留） | 跨境默认：后台 Cravatar 中国、前台关闭；混合：后台 Cravatar 中国、前台 Cravatar 国际 |
| 字体 Windfonts | 不呈现三项作用域（前台功能）。跨境 / 混合默认关 | 未绑定：既有「绑定后可用配额」 |
| 后台加速 `admin_assets` | 开关位 + 「即将提供」。值为 `on`（含迁移保留）时同时用「后台加速：已保留设置，4.1 起生效」 | 4.0 打开也不改写。开关可存 `on`/`off` |

### 状态

| 状态 | 内容 |
|------|------|
| 正常 | 各项显示当前 scope / 双值；`admin_assets` 显示「即将提供」 |
| 迁移保留 | `admin_assets=on` 时加「后台加速：已保留设置，4.1 起生效」 |
| 切换场景 | 改 `profile` 前确认（确认框文案若需要，原型用「确认你的站点场景」，不要另造「将重置连通性」长句除非先改词表）。确认后各项回到该场景默认 |
| 多站点 | 沿用 CO-06：网络策略 / 「已由网络设定」只读 / 「申请覆盖」。作用域呈现跟只读态一起出现，不另造词 |
| 保存 | 沿用 CO-01「已保存」 |
| 错误 | 沿用词表「暂时无法连接文派服务」句式；保存失败先登记再写（copy-guidelines 模板），本文件不发明 |

## 4. 原型 C 必须覆盖的画面（供 design-sop 清单）

向导：加载 / 有建议 / 无建议。  
概览：需确认提示出现；已确认不出现。  
连接优化：domestic 默认（公共库「后台与前台」、头像双侧 Cravatar 中国、`admin_assets`「即将提供」且为关）；crossborder 默认（公共库「仅后台」、头像前台关闭、`admin_assets` 开 + 「即将提供」）；迁移保留 `admin_assets=on` 那一行文案。

每个状态的 HTML 进 `docs/design/prototypes/`，认可进该页 `APPROVAL.md`，再拆 M-UI 任务。M-UI 任务书必须引用本文件、原型路径、认可日期、规格编号 `WZ-01` `OV-09` `CO-07`。
