## 行为规格

以 `docs/dev/release.md` 为准，冲突时以该文档为准并在报告说明。

版本号三处：`wp-china-yes.php` 头 `Version:`、`CHINA_YES_VERSION`、`package.json` 的 `version`（若 M1-01 未加 version 字段，本任务补上）。

### 现状（起草时，基于 `main` `63d662e`）

**`scripts/build-release.sh`：** 从插件头读 Version；rsync 排除 `.git`、`.github/`、`dist/`、`tests/`、`scripts/`、`docs/`、`vendor/`、`node_modules/`、`package.json`、`package-lock.json`；在包内 `composer install --no-dev` 后删除 composer.json/lock；`php -l`；zip。**没有** `npm run build`，**没有**排除 `src/Admin/app/`，**没有** SHA-256 输出，**没有**保留 `build/` 的专门步骤（若工作树无 build 则 ZIP 也不含）。

**`.github/workflows/ci.yml`：** jobs = `php`（7.4–8.4 + `tests/run-tests.sh`）、`package`（`needs: php`，跑 `build-release.sh`，校验 ZIP 不含 `.git|composer.json|lock|tests/|docs/|scripts/|package.json`）、`wordpress`（wp-env smoke）。**没有** `quality` / `frontend` / `e2e` / Plugin Check（这些应由 M1-01 / M1-10 添加；本任务在**当时 main 的真实文件**上改，若那些 job 已存在则不要删，只追加）。

### 本任务改动清单

**`scripts/build-release.sh`**

1. 若 `package.json` 存在：在 rsync **之前**于源码树执行 `npm ci && npm run build`（或要求 CI 已产出 `build/` 并作为输入）。失败则脚本非 0。
2. rsync 排除追加：`src/Admin/app/`、`webpack.config.js`、`.eslintrc.js`、`.prettierrc.js`、`.editorconfig`、`.nvmrc`、`phpcs.xml.dist`、`phpstan.neon.dist`、`phpunit.xml.dist`、`.grok-context/`、`tests/`（已有）、`docs/`（已有）。
3. **保留** `build/` 进包（不要 exclude `build/`）。
4. 打 ZIP 后计算 SHA-256，写 `dist/wp-china-yes-$VERSION.zip.sha256` 并 echo。
5. 校验：`unzip -Z1` 含 `wp-china-yes/build/index.js`（或实际 wp-scripts 产物名）；不含 `.git`、`tests/`、`docs/`、`src/Admin/app/`。

**`.github/workflows/ci.yml`**

1. 新增 job `plugin-check`（或并入 `quality`）：对安装后的插件跑 WordPress Plugin Check（`10up/action-wordpress-plugin-checker` 或 wp-env `wp plugin check`——以 M1 已选工具为准，不另引入第二套）。
2. `package` job：`needs` 包含已存在的 `php`、`quality`、`frontend`（若 job 名不同，对应当时文件，不要发明不存在的 job 名）。步骤：checkout → setup php+node → `npm ci && npm run build` → `bash scripts/build-release.sh` → Verify：
   - 不含 `.git`、`tests/`、`docs/`、`src/Admin/app/`、`webpack.config.js`、`phpstan.neon.dist`
   - 含 `build/` 下 js
3. `actions/upload-artifact` 同时上传 ZIP 与 `.sha256`。
4. **不要削弱**现有 PHP 7.4 矩阵（M4 前 3.x 门禁仍在）。4.0 PHP 下限未定时不把 7.4 从矩阵删掉。

**`docs/release/4.0-runbook.md`** 只写步骤，标明「代理默认不 tag、不 push main、不发 GitHub Release，除非任务书授权」。内容对照 `docs/dev/release.md`：冻结合入、同步版本、CHANGELOG、CI ZIP、SHA 对 HEAD、GitHub Release、分发切云桥（4.0 不再走 plat-api）。3.9.3 通道不在本文修改。

Plugin Check 失败门禁：任意 Fatal/Warning 级问题阻断；与「必须阻止发布的失败」表一致的项必须红。

- 不改 `docs/dev-plan/README.md`。

## 验收标准

1. `composer check` 全过。
2. `npm run build && bash scripts/build-release.sh` 产出 ZIP；`unzip -Z1 dist/*.zip | grep build/index.js` 有输出；`grep -E 'src/Admin/app/|phpstan.neon.dist'` 无输出。
3. SHA-256 文件存在且与 `shasum -a 256 dist/*.zip` 一致。
4. `git diff --stat` 限于 `scripts/`、`.github/workflows/ci.yml`、`package.json`（仅 version 字段若需）、`docs/release/4.0-runbook.md`。
5. 提交信息前缀 `build: `。
