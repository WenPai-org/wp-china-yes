## 4. 发现的问题

1. **任务书写的 `~/.local/bin/studio` 不是 CLI。** 该路径是 Electron GUI。无 DISPLAY 时 `--help` 直接退出。可用 CLI 在 `~/.studio/bin/studio`（1.15.0）。未改 VM 上的 PATH。
2. **3.x option 在纯 CLI 激活后不存在。** `option get wp_china_yes` 第一次失败。option 由框架 `WP_CHINA_YES_Options` 在 admin 路径 `save_defaults()` 写入；CLI 不是 `is_admin()`，`Service\Setting` 不加载。不是 Fatal。
3. **裸 `do_action('admin_menu')` 看不到叶子菜单。** 同样因为 Setting / `WP_CHINA_YES::setup()` 未在 CLI 跑，且 `add_submenu_page` 要当前用户有 `manage_options`。补上后菜单出现。
4. **`Plugin::create()` 只注册 5 个模块，没有 `diagnostics`。** 与任务书「六个模块 id」字面不符，与当前 `src/Core/Plugin.php` 一致。诊断走 CLI 文件，Site Health 键仍出现。
5. **`wp wpcy status` 的 `targets` 为空。** `doctor` 才探测。`cdnjs.admincdn.com` 一次 `fallback`（约 5s 超时），其余 ok。
6. **驻留 `verified()===false`。** 符合任务书对 M1-09b 未完成重签的预期。检出仍停在 `7420b62`（M1-09b 任务书提交，不是重签产物）。
7. **symlink 可用。** 未改 rsync。创建站点时用了 `--file-access all-files`，否则 Native PHP 默认只读站点目录，可能读不到 `~/wt/wpcy-main-studio`。

无 PHP Fatal、无 PHP Warning 写入 `debug.log`。
