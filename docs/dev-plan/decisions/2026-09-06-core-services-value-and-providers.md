# 统筹决定：核心服务的品牌归属与价值反馈、双供应商、WPCY 作为渠道

日期：2026-09-06 夜。决定人：feibisi（产品）/ linuxjoy（统筹）。状态：**已定稿**；D1–D6 是 feibisi 原话落成的决定，§"统筹建议"是待 feibisi 点头的想法。

## 起因

feibisi 看过原型 E v5.4 后的反馈（原话要点）：

- "线路健康这个圈看上去就很廉价"；"来自文派要么弄成一个大块背景，现在一堆按钮看着很烦"；Phosphor 图标不喜欢，换 RemixIcon；e.css 有重复代码。
- "WPCY 插件的核心功能对应国内用户是解决功能无法正常使用，对于跨境用户是解决他们的痛点，而且这是文派 WordPress 生态的连接器，我们应该提供更多价值展示，比如没有启用哪些核心服务或者用户站点无法访问某项服务时，是通过我们的服务恢复，希望可以在概览的模块里面有些设计和状态反馈。"
- "公共库源这个是 adminCDN 提供的服务、后续可能也需要类似 Windfonts 这样的限制；WordPress.org 的国内替代更新源是 WenPai.org 提供的，旧插件里面都有；这些核心服务是免费提供所以至少得让人知道对应的品牌和服务商。"
- "WPCY 插件最大的作用应该就是我们自己的产品服务渠道和分发，服务需要提供两个供应商，一个是薇晓朵、一个是文派集市，这个可以参考文派云桥 WP 插件。用户绑定站点依旧是以文派为主，但是供应商可以选择薇晓朵和其他的（目前不会有其他的），这样薇晓朵提供的一些服务和产品也可以直接通过 WPCY 插件使用。"
- "我们的主要服务人群是跨境出海这群用户。"

统筹核实：

- 3.8 的选项文案与 readme 都写明 WenPai.org 更新源、adminCDN 加速节点、Cravatar 头像、Windfonts 字体；4.0 原型 E 到 v5.4 只在"来自文派"资源带里提到品牌，功能行本身没有服务商归属。
- 文派云桥插件（FeiCode `WenPai-org/wpbridge`，本地 `~/wt/wpbridge`）`includes/Commercial/Vendors/PresetRegistry.php` 预置两个供应商：`wenpai-marketplace`（文派集市，`status: coming_soon`）与 `weixiaoduo-mall`（薇晓朵商城，`https://mall.weixiaoduo.com`，`status: available`，`subscription_vendor: true`）；连接方式 `wc_am`（WooCommerce API Manager：邮箱 + 授权密钥）；连接后商业插件的更新与授权经云桥代理（`BridgeManager` / `SubscriptionManager` / `AutoMatcher`）。这就是 feibisi 说的"供应商"。
- 4.0 现有 REST 没有供应商概念；`/binding` 只有文派站点身份，`/entitlements` 只有文派服务端权益。

## 决定

### D1 每项核心服务都标服务商品牌

界面上每一项连通性功能都写清"由谁提供"，格式 `功能 · 服务商`，服务商名用品牌原文（不翻译、不加"云"字）：

| 功能（用户词） | 服务商（品牌原文） | 说明 |
|----|----|----|
| WordPress 更新与安装包 | **WenPai.org** | 文派开源维护的 WordPress.org 国内镜像 |
| 公共库加速（Google Fonts / Ajax / jsDelivr / CDNJS / Emoji） | **adminCDN** | 文派维护的公共库国内节点；后续可能有 Windfonts 式的限额或线路限制，界面从现在起把它当"服务方"而不是"设置项"（预留服务方状态：正常 / 限流 / 不可用） |
| 头像 | **Cravatar** | 中国线路 cravatar.cn / 国际线路 cravatar.com |
| 中文字体 | **Windfonts** | 需绑定；限额由 Windfonts 平台自己做 |
| 站点绑定 · 小工具 · 兼容性信息 | **文派服务** | api.wenpai.net 一族；对用户只说"文派服务" |

这些核心服务**免费**，品牌露出不是商业化，是让用户知道谁在替他扛。同一品牌在概览、设置、诊断、服务页用同一写法。

### D2 概览以"核心服务连通"为主视觉，取消分数环

概览 Hero 右侧不再是分数环。换成**核心服务连通栈**：每项核心服务一行——图标块、功能名、服务商、状态词。状态词四个，且必须与线路检查数据一致：

| 状态 | 何时 | 界面词 | 色 |
|----|----|----|----|
| 已接通 | 原始源在本站不可达或慢，现在经服务商接通（国内站的常态） | 已接通 · 经 WenPai.org | 正常绿 |
| 直连 | 本场景不需要我们（跨境站更新直连 WordPress.org） | 直连 | 中性灰 |
| 已回退 | 服务商暂时不可达，已回原始源，功能不中断 | 已回退 · 服务商不可达 | 注意琥珀 |
| 未启用 | 该项关闭；给一个"启用"入口和一句它能带来什么 | 未启用 · 启用后 … | 中性灰 + 幽灵按钮 |

两种场景的叙事不同，同一组件：**国内站**说"原本用不了的，现在能用了"（Google Fonts 打不开 → 经 adminCDN 接通；Gravatar 空头像 → 经 Cravatar 接通；WordPress.org 更新超时 → 经 WenPai.org 接通）；**跨境站**说"人在国内操作海外后台不再等"（后台资源经 adminCDN 接通、后台头像经 Cravatar 接通、心跳与仪表盘外链已减少；更新直连）。

"过去 7 天为你处理"三张统计卡保留（`/stats`），"线路状态 / 最近动态"保留，但线路列表每行加服务商列。

### D3 "来自文派"改为一个整块

不再是一排排小按钮。一个带浅色底的整块区（次表面），左边一句定位（"文派叶子是文派 WordPress 生态的入口：WenPai.org 更新源、adminCDN 公共库、Cravatar 头像、Windfonts 字体，全部免费"），右边按品牌分三到四栏、每栏一个品牌名 + 一行说明 + 一个文字链接。跨境站多一栏"跨境店工具"（薇晓朵）。链接总数 ≤ 8。

### D4 服务：文派绑定为身份层，供应商可连接

- **绑定**仍然只有一个对象：文派（站点身份、匿名、`/binding`）。不改。
- 新增**供应商**层，两个预置：**文派集市**（`coming_soon`，界面显示"即将开放"）与**薇晓朵商城**（可连接）。连接方式沿用云桥：邮箱 + 授权密钥；连接状态：未连接 / 已连接（账户邮箱掩码 + 连接日期）/ 授权失效。目前没有第三个供应商，也不做"自定义供应商"输入（云桥的 `custom-bridge-api` 不并入 4.0）。
- 连接供应商后，该供应商名下用户已购的产品 / 服务出现在"可用服务"列表（更新经云桥或 wenpai-updater、授权经供应商），未购的按服务端露出规则显示"了解 →"。
- 服务页信息架构改为三段：**站点绑定**（文派）→ **供应商**（文派集市 / 薇晓朵商城）→ **可用服务与小工具**。
- 供应商是否需要先绑定文派：**需要**（先有站点身份，再连供应商）。

### D5 WPCY 是渠道与分发，不是功能商店

叶子不卖功能。它做三件事：接通核心服务（免费）、分发文派系产品与更新、把供应商的服务带到站点里。商业内容露出条件由服务端规则下发（已定，见 `2026-09-06-site-profile-and-scope.md` 商业模型节）；`domestic` 几乎不露出；`crossborder` / `mixed` 是主要服务人群，服务露出与文案以他们为第一读者。

### D6 视觉：图标换 RemixIcon；原型 CSS 去重

- 图标库改为 **RemixIcon**（Apache 2.0），line 风格；原型从本地 `node_modules/remixicon/icons/**/*.svg` 内联，不走 CDN；React 实现用 `@remixicon/react`（同名组件，`Ri…Line`）。`build.py` 的映射表是唯一来源。取代 v5.4 的 Phosphor 决定与 v1.0 规格 §5 的 Phosphor 条目。
- `e.css` 五个版本块叠加出的重复规则由 Grok 清理成一份单层样式，视觉零变化（截图 diff 验）。

## 统筹建议（未定，等 feibisi 点头）

面向跨境出海这群人，除了上面的，还可以做：

1. **"为你解决的痛点"用前后对照说话。** 概览统计卡加一个"若不用叶子"的对照值：后台一次加载 Google Fonts 从 12 秒超时 → 0.2 秒；Gravatar 空头像 → 全部显示；更新检查 45 秒超时 → 1.1 秒。数据来自浏览器测速的"原始源 vs 接通后"成对结果（`/diagnostics/client-probe` 允许名单已补成对主机）。这比"节省 1.2 GB"更能让跨境用户感到痛点被解决。
2. **团队多管理员的测速共享。** 跨境店常常几个人在国内轮班操作后台；诊断页的浏览器测速按管理员保存最近一次并在概览上显示"你与另 2 位管理员的测速"，让老板一眼看到是谁的网络慢。
3. **跨境店场景包。** 在向导第 2 步"已为你做的"之后，跨境站多一步"你可能还需要"：微信支付 for WooCommerce、订单微信通知、中文字体（给中国买家看的页面）——全部走供应商（薇晓朵），文案用"了解 →"。这是 D5 的第一个落地位置，不打断向导。
4. **管理员浏览器语言与站点语言分离。** 跨境站前台是 en_US，管理员要看中文后台；叶子可以在设置里给"后台语言跟随管理员"一个开关（WordPress 已支持用户语言，但很多人不知道），属于"减少等待"之外的第二个跨境痛点。
5. **服务商状态页入口。** D1 把 adminCDN / WenPai.org 当服务方之后，诊断页给一个"服务商状态"链接（status.wenpai.org 或类似），让用户区分"我的网络问题"和"服务商的问题"。需要 devops 确认有没有状态页。

不建议做的：不在叶子里做商业插件的授权代理（云桥的 `LicenseProxy`，GPL 与合规风险由云桥自己扛）；不做自定义供应商；不做"分数"类指标。
