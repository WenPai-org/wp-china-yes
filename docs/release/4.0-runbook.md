# 4.0 发版 runbook

状态：清单（执行时勾选）· 2026-09-04
产品线：4.0（新品）。与 3.9.x LTS **分开**；3.9.3 通道见 `docs/release/3.9.3-runbook.md`，本文不改它。
角色：代理执行 · 统筹 linuxjoy 验收 · 产品 feibisi 放行。
依据：`docs/dev/release.md`、`docs/dev/testing.md` 发布包检查。
仓：`WenPai-org/wp-china-yes`。开发主线：`main`。

**代理默认不 tag、不 push `main`、不发 GitHub Release，除非任务书授权。** 本清单只写步骤，M2-08 不执行发版。

---

## 0. 授权与禁区

未写明授权时：

- 不打生产 tag（`v4.x.y`）
- 不 `git push` `main` / `master`
- 不创建 GitHub Release
- 不上传 dl1、不改 plat-api（4.0 **不再走** `api.wenpai.net/china-yes/version-check`）
- 不改 3.9.x 更新通道

公告与 changelog **不写**面向用户的报告开关说明；不出现「遥测开关」、opt-in 一类用户文案（报告常开、界面不露出，见定稿 §7.1 / §7.2）。

## 1. 冻结合入

`main` 冻结：禁止再合功能。发版当天 HEAD 即被测对象。

```bash
git fetch origin
git checkout main
git pull --ff-only origin main
git log -1 --oneline
# 该 HEAD 的 CI：php（含 7.4 矩阵，PHP 下限未定前不得删）+ quality + frontend + plugin-check + package + wordpress 全绿
```

判据：冻结提交已合入；CI 全绿。旧候选 ZIP / SHA 作废，不得复用。

---

## 2. 同步版本（三处）

版本号三处必须相同：

- `wp-china-yes.php` 插件头 `Version:`
- 常量 `CHINA_YES_VERSION`
- `package.json` 的 `version`

```bash
bash scripts/sync-version.sh 4.0.0
grep -n "^ \* Version:" wp-china-yes.php
grep -n "CHINA_YES_VERSION" wp-china-yes.php
node -e 'console.log(require("./package.json").version)'
```

判据：三处均为本次版本（例 `4.0.0`）。semver 见 `docs/dev/release.md`：补丁 `4.x.y`，功能 `4.(x+1).0`，破坏性 `5.0.0`。

## 3. CHANGELOG

把 `CHANGELOG.md`「未发布」切成对应版本段，日期为发版日。

```bash
bash scripts/changelog-cut.sh 4.0.0 2026-09-04   # 日期换成发版日
git diff CHANGELOG.md
```

判据：出现 `## v4.0.0 - <发版日>`；「未发布」仍在且为空。文案不写面向用户的报告开关。

## 4. CI ZIP 与 SHA-256

冻结 HEAD 上 `package` job 产出 ZIP。ZIP 的 SHA **必须对应该 tag 的 HEAD**（tag 在下一步；先记下本 HEAD）。

```bash
# 等 package job；下载 artifact wp-china-yes-release
# 内含 dist/wp-china-yes-<version>.zip 与 .sha256
unzip -tq wp-china-yes-4.0.0.zip
unzip -Z1 wp-china-yes-4.0.0.zip | grep 'build/index.js'
unzip -Z1 wp-china-yes-4.0.0.zip | grep -E 'src/Admin/app/|phpstan.neon.dist' && echo FAIL || echo OK_excluded
FILE_HASH="$(awk '{print $1}' wp-china-yes-4.0.0.zip.sha256)"
SUM_HASH="$(shasum -a 256 wp-china-yes-4.0.0.zip | awk '{print $1}')"
test "$FILE_HASH" = "$SUM_HASH" && echo SHA_OK
```

本地等价（不替代 CI）：

```bash
npm run build && bash scripts/build-release.sh
unzip -Z1 dist/*.zip | grep build/index.js
shasum -a 256 dist/*.zip
```

判据：

- ZIP **含** `wp-china-yes/build/index.js`（wp-scripts 产物）与生产 Composer 依赖
- ZIP **不含** `.git`、`tests/`、`docs/`、`src/Admin/app/`、`webpack.config.js`、`phpstan.neon.dist`、`composer.json` / `composer.lock`、`package.json`
- `.sha256` 与 `shasum -a 256` 的哈希一致
- Plugin Check job 无 Fatal / Warning 级问题（任意此类问题阻断发布）

「必须阻止发布的失败」见 `docs/dev/testing.md`：Fatal / Warning / Notice / Deprecated；镜像失败无法回源；未绑定时免费能力失效；凭据进日志/导出；迁移丢失保留设置或删除 `wp_china_yes`；非管理员可改设置；远程失败仍显示成功；ZIP 与测试 HEAD 不一致。

## 5. tag 与 GitHub Release

**仅在产品放行且任务书授权后：**

```bash
git tag -a v4.0.0 <main-HEAD-sha> -m "v4.0.0"
# push tag 须授权。禁止 push main。
```

GitHub Release 附件：该 ZIP + `.sha256`。说明从 `CHANGELOG.md` 对应版本段摘。readme 要求用户从 Release 下载，不要下源码包。

Forgejo 与 GitHub 谁是分发源：发版当天核清，写回定稿 §9；**本 runbook 不发明「以谁为准」**。

---

## 6. 分发切云桥

4.0 更新通道目标：云桥 `updates.wenpai.net`（定稿 §7.1-7）。**4.0 不再走 plat-api**（`api.wenpai.net/china-yes/version-check` 只服务 3.9.x，见 `docs/release/3.9.3-runbook.md`）。

步骤（由 devops / 已授权执行者，插件仓代理不改生产机）：

1. 确认 CI ZIP SHA 已对冻结 HEAD。
2. 按当时有效的云桥发版规程登记版本与包地址（具体字段以云桥仓为准，本文不编）。
3. 核站点更新检查返回 4.0 版本与该 ZIP。
4. 3.9.x 通道保持 plat-api，不在本步改 `VersionCheck.php`。

---

## 7. 站点回滚（4.0 → 3.9.x）

4.0 **不写** 3.x option `wp_china_yes`（只读迁移）；3.9.x **不读** 4.0 option。

1. 停用 4.0
2. 安装 3.9.x 发行 ZIP（从当时有效的 3.x 分发通道）
3. 启用 3.9.x —— 仍读原 `wp_china_yes`；4.0 option 留在库里无害
4. 不要手工把 4.0 键写进 `wp_china_yes`

凭据在 `wpcy_site_identity`，3.9.x 不使用。卸载 4.0 时是否删除 4.0 option，按迁移 spec，默认保留至少一个 4.x 小版本。
