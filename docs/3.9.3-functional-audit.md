## 已修复错误

1. `Service/Maintenance.php` 注册不存在的 `check_maintenance_mode()`、`add_admin_bar_notice()`，前台和后台均会 PHP Fatal。
2. `Service/Memory.php` 在 `plugins_loaded` 执行期间再次注册同一阶段回调，功能实际从未启用。
3. Windfonts 默认字体和子集参数已经不被当前 API 接受；`crossorigin=anonymous` 又会强制触发服务端未提供的 CORS 校验。
4. 评论置顶 AJAX 处理器只在评论列表页面的资源加载阶段注册，独立 `admin-ajax.php` 请求始终返回 `0`。
5. PHP 7.4 声明与代码不一致：首方代码调用 PHP 8 的 `str_contains()`。
6. PHP 8.2+ 会提示 `utf8_decode()` 废弃。
7. 当前 WordPress/jQuery Migrate 会报告设置框架使用 `.keydown()` 与 `jQuery.isArray()`。
8. 语言和媒体功能面对不完整旧设置时存在 array-key warning 风险。
9. Git worktree 的 `.git` 是文件而非目录，原构建排除规则失效，发布 ZIP 会夹带 Git 元数据与 Composer 构建清单。

## 仍需在 4.0 处理

- 新安装默认只显示 welcome/store/admincdn/cravatar/other/about 六个 section；section 选择器本身位于默认隐藏的 brand section，大量功能对新用户实际上不可配置。
- ArkPress、墨图云集、飞秒邮箱、无言会语、必胜区块、灯鹿用户、WooCN、LELMS、Wapuu 等只有设置项或跳转入口，没有对应本地 Service 行为，不能算作插件功能。
- 旧设置框架仍有大量全局类与 Composer PSR-4 警告；3.9.3 只修复运行错误，不继续扩建该框架。
- Windfonts 字体目录会变化，4.0 应从服务端动态读取可用字体，而不是继续在插件中硬编码字体族。
- `Service/123-Maintenance.php`、Monitor、Widget、ModernSetting 等退役或未装载文件仍在源码中，4.0 应删除而不是继续维护两套实现。

## 验收判据

- 全部功能矩阵页面返回预期 HTTP 状态。
- 后台展开全部 26 个设置 section 后没有浏览器 console error/warning。
- 设置 AJAX 保存返回 `Settings saved.`，保存后 option 含 71 个字段。
- `debug.log` 无插件 PHP Warning、Notice、Deprecated、Fatal 或 Uncaught 错误。
- 独立 PHP 测试、真实 WordPress 新装/升级烟测和发布 ZIP 完整性均通过；ZIP 不含 `.git`、根目录 Composer 清单、测试与文档。
